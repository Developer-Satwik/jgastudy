# Tool and file rules

## Use the right tool for the evidence

| Need | Preferred route | What must be preserved |
| --- | --- | --- |
| Discover and inspect public evidence | Web search, original publisher pages and linked reports | Exact URL, access date, source state and context |
| Read a public PDF or image-based table | PDF text extraction plus page rendering/screenshot where necessary | Original source, page/table locator and verified values |
| Navigate a dynamic viewer or legitimately available account | Browser only when public tools are insufficient and access is enabled | What was actually seen; no bypass or invented access |
| Analyse public data and reconcile definitions | Local code and structured registers | Inputs, transformation, units and reproducible results |
| Build the financial workbook | Spreadsheet skill and bundled authoring tools | Editable formulas, labelled assumptions and recalculated results |
| Produce Word/PDF/PowerPoint outputs | Relevant document, PDF and presentation skills | Editable originals and rendered visual QA |
| Compare or challenge an interpretation | A bounded second researcher or independent review | Actual supporting/counterevidence and unresolved disagreement |
| Use private client material or participant input | Only the agreed secure collection/storage/tools | Permissions, access and confidentiality status |

Tool availability does not itself grant authority to send, buy, upload private data, activate recording, book events or sign. No connector, browser, cloud platform or AI tool is used merely to show activity. Current work needs public research and a local project record, not a new app or website.

## One source of truth

Keep the master registers in `02-evidence/registers` and synthesis in `05-analysis`. Module notes link to IDs. Full third-party sources are captured once when needed and permitted, not copied into each chapter.

ID prefixes: SRC source; CLM extracted claim; Q question; P participant; INT contribution; OBS observation; FND finding; ASM financial assumption; CHT chart; D deliverable; DEC decision. Never reuse a retired ID.

The default trace is source and locator → claim or observation → finding → recommendation/chart → deliverable. Record transformations rather than manually retyping inconsistent numbers in several files.

Use ISO dates, stable filenames and `v0.1`, `v0.2` revisions. Freeze checkpoint copies when shared. Keep an append-only decision/change log. Do not create files called final-final.

## Capture only useful evidence

For a stable original PDF, keep one lawful source file and record the relevant pages. For a changing product, licence or price page, a dated capture can help verify the observed offer. Preserve a file hash only for an actual retained capture.

No screenshots of blank pages, every scroll or irrelevant browser chrome. Do not confuse a screenshot with proof of a study's method. Raw browser screenshots remain internal unless needed and cleared for handover.

## Sensitive material

This workspace is not declared encrypted or access-controlled. It is outside a Git repository as checked during setup, but it could later be copied or published. Do not place identifiable participant information here. The local ignore rules are a backstop, not a security guarantee.

Do not upload the project directory wholesale to GitHub, Sites, Netlify or any public service. Client handover copies only reviewed outputs and appropriate evidence, never the whole working tree. Council identity recognition, raw research input and sponsor access require separate consideration.

## Session close

Update current status, source/search records, open decisions and the active work package. Save exact approved question versions and source locators when fieldwork begins. Keep the user informed of meaningful findings and dependencies without treating a draft or queued source as a completed result.
