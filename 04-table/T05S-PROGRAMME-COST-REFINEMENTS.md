# Programme cost refinements after the service/sales review

1 November 2026. Internal implementation requirements for the unfinished full T05 model. Preserve the first component, its fifteen unit definitions and the original seventy inputs.

| Condition | Record only when relevant | Required treatment |
| --- | --- | --- |
| Work and completion state | Work begun/incurred, completed output, cancelled/deferred work and necessary remainder. | Count actual effort once. A zero completed-unit count does not erase preparation. Use a supported allocation only where its denominator exists. |
| Audience and performer fit | Actual questions, permitted audience, confidentiality, capable available owner and extra presenters/reviewers. | Joint sessions are conditional. Count every necessary person's actual task time without multiplying the whole unit by each role. |
| Reuse and handling | Exact asset/version, saved work, necessary update and shared versus individual release/response. | Credit the saved task once and retain genuine recipient-specific work. A repeated label is not another task, while a different use may require work. |
| Task and market fit | Buyer decision, public/internal alternatives, country, service object, edition and evidence period. | Do not infer a paid gap, supplier capability or resource rate from a guide, global office, podcast or model recommendation. |
| Term and remaining obligations | Benefit period, actual delivery/cash dates and work still owed after a campaign or sales offering ends. | Carry commitments over the correct periods. No automatic renewal, same-period delivery or discharge of an existing obligation. |
| Delivery and cost basis | Appropriate owner/skill, actual package or task basis, retained work and applicable rate/cash classification. | Keep unknown values visible, reconcile shared labour once, and add relevant non-labour cost before pricing or a full result. |

## Implementation order

First preserve the existing catalogue as a comparison for its defined units. During full programme integration, add an identifiable non-completion/exception work allowance and a schedule of remaining fulfilment obligations. These can be simple records, not a separate questionnaire or elaborate new system. Link each to the existing task, period and actual scope so the same hours cannot appear twice.

Where several activities share an asset, identify the common work and the remaining effort separately. A documented period average may be appropriate; it should not hide zero-completion work, materially different service scopes or an obligation extending outside that period. No generic reuse discount or cancellation probability is adopted.

A free content correction can consume real labour. Retain any additional resource effort once under its appropriate production/customer-handling task, preserving the current agreement's correction duties and adding no new fee by assumption. The same replacement send must not appear as both a distribution run and a second resolution task.

Before the complete model can pass, test a no-sale period with proposal work, a cancelled service with preparation, compatible versus separate audiences, a genuinely reused asset, additional presenters, a shared paid/free release and an order with future delivery. Keep bank cash, resource cost, invoice/order and fulfilled benefits distinct.

The [twelve constructed applications](research-notes/t05s-second-check/cost-applications.json) provide examples, not actual activities or adopted scenario inputs. Actual scope, capability, rates, volumes and funding remain to be established. Return to the [second-check findings](T05S-SECOND-CHECK-READOUT.md).
